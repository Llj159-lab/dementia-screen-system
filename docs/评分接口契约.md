## 2. 输入契约

### 2.1 纯函数入口

```ts
score(scaleCode: string, answers: Answers, patient?: PatientCtx): ScoreResult
```

```ts
type ScaleCode = "SCD_Q9" | "GDS" | "FAQ" | "MMSE" | "MOCA_B" | "CDR";

type Answers = Record<string, string | number>;
// 例：{ "MMSE_01": "1", "GDS_05": "否", "CDR_MEMORY": "0.5" }

interface PatientCtx { educationYears?: number; }
```

### 2.2 作答值匹配规则

- key = 题目编码，**保留 snake_case**（`MMSE_01` / `GDS_05` / `CDR_MEMORY`）。
- value 可为**选项编码**或**选项文本**；先按 `code` 精确匹配，未命中再按 `text` 匹配；
  匹配前做 `String(value).trim()`。
- FAQ 的 `"NA"` 是选项编码（`isNa=true`），**不计入总分**，但会记录到 `itemScores`（score=0）。

### 2.3 各量表入参要求

| 量表 | 必答 | 是否需 `educationYears` |
|---|---|---|
| SCD_Q9 | 9 题全部 | 否 |
| GDS | 15 题全部 | 否 |
| FAQ | 10 题全部 | 否 |
| MMSE | 30 题全部 | **是** |
| MOCA_B | 24 题全部 | **是** |
| CDR | 6 个功能域全部 | 否 |

## 3. 输出契约

```ts
interface ScoreResult {
  scaleCode: string;
  scaleName: string;
  totalScore: number;
  subScores: Record<string, number>;   // 分项得分（SUM 量表为 {}）
  itemScores: ItemScore[];             // 逐题得分
  resultLabel: string;                 // 解释；无界值时为 ""
  cutoffGroup: string | null;          // 界值分组键
  cutoffValue: number | null;          // 界值分
  isAbnormal: boolean | null;          // 是否异常；无界值时为 null
  extra: Record<string, unknown>;      // CDR 附加信息
}

interface ItemScore {
  itemCode: string;
  itemText: string;
  domain: string | null;
  answerValue: string;
  optionCode: string | null;
  score: number;
}
```

### 3.1 各字段在各计分类型下的取值

| 字段 | SUM（SCD_Q9/GDS/FAQ） | ITEMIZED（MMSE/MoCA-B） | CDR |
|---|---|---|---|
| `totalScore` | 选项分值累加 | 各域得分之和 | 整体 CDR（0/0.5/1/2/3） |
| `subScores` | `{}` | 按认知域汇总 | 6 功能域得分 |
| `resultLabel` | LEVEL 分级解释；SCD-Q9 无界值 → `""` | 教育分组解释（如「文盲（0 年）」） | `CDR_LEVELS[total]`（如「轻度痴呆（CDR=1）」） |
| `cutoffGroup` | 分级带（如 `"12-15"`）；SCD-Q9 → `null` | 教育分组键（如 `"中学及以上"`） | `null` |
| `cutoffValue` | 带上界（如 `15.0`）；SCD-Q9 → `null` | 界值分（如 `24.0`） | `null` |
| `isAbnormal` | LEVEL 的 `isAbnormal`；SCD-Q9 → `null` | `total ≤ threshold` | `total > 0` |
| `extra` | `{}` | `{}` | `{ cdrSb, cdrGlobal, domainScores, cdrSbRange }` |

### 3.2 CDR 的 `extra` 结构

```ts
{
  cdrSb: number;            // CDR-SB = 6 域得分之和（0~18）
  cdrGlobal: number;        // 整体 CDR（同 totalScore）
  domainScores: Record<string, number>;  // 6 域得分（同 subScores）
  cdrSbRange: "0-18";
}
```

### 3.3 界值规则回顾

- **LEVEL（GDS）**：`0-4 正常 / 5-8 轻度抑郁 / 9-11 中度抑郁 / 12-15 重度抑郁(异常)`。
- **LEVEL（FAQ）**：`0-5 正常 / 6-8 SCD 参考范围 / 9-30 MCI（异常）`。
- **EDUCATION（MMSE）**：`0→17 / 1-6→20 / ≥7→24`，`total ≤ threshold` 异常。
- **EDUCATION（MoCA-B）**：`≤6→19 / 7-12→22 / ≥13→24`，`total ≤ threshold` 异常。
- **CDR**：Morris(1993) 整体评分，`>0` 判异常；CDR-SB = 6 域之和。

## 5. 后端接入步骤

后端仓库现状（已核查）：`backend/src/business/scoring.ts` 中 SUM / ITEMIZED 已能计分，
但 **CDR 是 `pending_task1_engine` 桩**（返回 null 总分），且 EDUCATION 界值的
`resultLabel` 被硬编码为「筛查异常 / 筛查未见异常」，丢失真实 `result_label`，且无 `subScores`。

接入方式（推荐，改动最小）：

1. **拷贝源码**：把 `ts/src/` 与 `ts/adapters/backend.ts` 拷入后端仓库
   （例如 `backend/src/scoring/`，保持 `index.ts` 为统一入口）。

2. **替换计分桩**：在 `scoring.ts` 的 `calculateScore` 中，用
   `calculateScoreForBackend` 替换原计分逻辑（含 CDR 桩）：

   ```ts
   import { calculateScoreForBackend } from "../scoring/adapters/backend.ts";

   const summary = calculateScoreForBackend(
     config.code,                // 量表编码
     submitted,                  // SubmittedAnswer[]
     patient.educationYears,     // number | null
     (msg) => new AuthError(400, 40001, msg),  // 复用后端错误码体系
   );
   ```

3. **保留既有输入校验**：后端原有的 `itemCode / optionCode / 重复项` 校验逻辑保持不变；
   本包只负责「作答 → 计分」这一段。

4. **可选扩展字段**：`ScoreSummary` 新增的可选字段 `subScores / cutoffGroup / cutoffValue / extra`
   **均为可选**，前端无需变更；后端可决定是否落库（建议 `sub_scores` 以 JSON 存，同任务 1 表结构）。

### 5.1 适配器关键函数

| 函数 | 作用 |
|---|---|
| `answersFromSubmitted(answers)` | `SubmittedAnswer[] → Answers`；跳过 `answerStatus !== "answered"` 与 `optionCode` 为空者 |
| `toScoreSummary(result, maximumScore)` | `ScoreResult → ScoreSummary`；`resultLabel || null`、`isAbnormal ?? null`、`scoringStatus:"calculated"` |
| `calculateScoreForBackend(code, submitted, years, errorFactory?)` | 统一入口：`getScale(code).scoreMax` 作 `maximumScore`；`Error → errorFactory(msg)` |

> `errorFactory` 默认 `(msg) => new Error(msg)`；后端传 `AuthError` 工厂即可复用其错误码体系，
> 使适配器**不依赖后端 auth 模块**（自包含）。

### 5.2 `ScoreSummary`（后端既有必填字段 + 新增可选字段）

```ts
interface ScoreSummary {
  totalScore: number | null;
  maximumScore: number | null;
  resultLabel: string | null;
  isAbnormal: boolean | null;
  scoringStatus: "calculated" | "pending_task1_engine";
  scoringMethod: string;                 // "task1-engine:<scaleCode>"
  warning: string | null;
  // ↓ 新增可选字段（后端可忽略）
  subScores?: Record<string, number> | null;
  cutoffGroup?: string | null;
  cutoffValue?: number | null;
  extra?: Record<string, unknown> | null;
}
```

## 7. 安全与注意事项

1. **不要提交** `.env`、数据库密码、云 API 密钥、`data/users.json`、`data/files.json`、
   本地上传文件或真实患者资料（沿用后端既有安全约束）。
2. **计分唯一入口**：后端持久层 / UI 展示仍可用 `task1-scale-configs.json`，
   但**计分必须走本包 `score()`**，避免两处计分逻辑漂移。
3. **教育年限来源**：MMSE / MoCA-B 的界值匹配唯一依据是 `patient.educationYears`（整数 ≥0）；
   后端需保证该字段真实可靠，`education_level` 展示字段不参与计分。
4. **FAQ NA**：`optionCode === "NA"` 计 0 分、不影响总分；后端落库时应区分「NA」与「作答 0」。
5. **CDR 分值域**：`{0, 0.5, 1, 2, 3}` 均为 IEEE-754 精确表示，代码用 `===` 直接比较；
   后端若以 JSONB 存储，注意 `0.5` 不要被序列化为字符串。
6. **反序已内化**：GDS 反序题（1/5/7/11/13）的「是=0/否=1」已体现在 `config.ts` 的选项分值中，
   后端 UI 无需（也不应）再写反向逻辑。
